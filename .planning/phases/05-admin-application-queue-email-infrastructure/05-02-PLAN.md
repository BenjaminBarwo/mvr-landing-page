    **1. Create Server Component page at `src/app/admin/(dashboard)/applications/page.tsx`:**

    This is a Server Component (no `"use client"` directive). It reads URL search params and fetches data from Supabase.

    Props interface:
    ```typescript
    interface Props {
      searchParams: Promise<{
        status?: string
        page?: string
        search?: string
        role?: string
      }>
    }
    ```

    **CRITICAL: `searchParams` is a Promise in Next.js 15+. Must `await searchParams` before accessing properties.**

    Data fetching logic:
    - Use `createClient()` from `@/lib/supabase/server` (NOT supabaseAdmin — Server Component runs in admin context, auth is verified by middleware + layout)
    - Page size: 25 (per CONTEXT locked decision)
    - Default sort: `created_at` descending (newest first, per CONTEXT)
    - Calculate `from = (page - 1) * 25` and `to = from + 24` for `.range(from, to)`
    - Base query: `supabase.from('applications').select('*', { count: 'exact' }).order('created_at', { ascending: false }).range(from, to)`

    Status filtering (use URL param `status`):
    - `status=partial` → `.lt('step_completed', 3).eq('status', 'draft')` — partial applications tab
    - `status=submitted|approved|rejected|waitlisted` → `.eq('status', params.status).gte('step_completed', 3)`
    - No status param (default) → `.neq('status', 'draft')` — all submitted+ applications

    Search filtering (URL param `search`):
    - `.or(\`first_name.ilike.%${params.search}%,email.ilike.%${params.search}%\`)`

    Role filtering (URL param `role`):
    - `.eq('role', params.role)`

    Status count query (for tab badges):
    - Run a separate query to get counts per status. Two approaches:
      a) Multiple count queries per status (simpler but more queries)
      b) Single query grouping by status
    - Recommend approach (a) — run 5 separate `.select('*', { count: 'exact', head: true })` queries for submitted, approved, rejected, waitlisted, and partial (draft + step < 3)
    - Pass counts as `statusCounts: { submitted: N, approved: N, rejected: N, waitlisted: N, partial: N }` to the client table component

    Pass data to client component:
    ```tsx
    <ApplicationsDataTable
      data={applications ?? []}
      totalCount={count ?? 0}
      page={page}
      pageSize={25}
      statusCounts={statusCounts}
      currentStatus={params.status ?? 'all'}
      currentSearch={params.search ?? ''}
      currentRole={params.role ?? ''}
    />
    ```

    **1. Create Server Actions at `src/app/admin/(dashboard)/applications/actions.ts`:**

    `"use server"` directive.

    **a) `updateApplicationStatus` action:**

    Input validation with Zod:
    ```typescript
    const updateStatusSchema = z.object({
      applicationId: z.string().uuid(),
      status: z.enum(['approved', 'rejected', 'waitlisted', 'submitted']),
      reason: z.string().optional(),
    })
    ```

    Steps:
    1. Verify caller is an `approver` using `createClient()` + `getUser()` — check `user.app_metadata.role === 'approver'`. If not, return `{ error: 'Unauthorized: approver role required' }`.
    2. Validate input with Zod schema. If rejection, verify `reason` is non-empty — return `{ error: 'Rejection reason is required' }` if missing.
    3. Fetch the application from DB using `supabaseAdmin.from('applications').select('first_name, email, role, primary_zip, status').eq('id', applicationId).single()`. If not found, return `{ error: 'Application not found' }`.
    4. Store the `previousStatus = app.status` before update.
    5. Update application: `supabaseAdmin.from('applications').update({ status, reviewed_by: user.id, reviewed_at: new Date().toISOString() }).eq('id', applicationId)`. If update fails, return `{ error: 'Failed to update application' }`.
    6. Insert status history record: `supabaseAdmin.from('application_status_history').insert({ application_id: applicationId, from_status: previousStatus, to_status: status, changed_by: user.id, reason: reason ?? null })`.
    7. Determine email type: If `previousStatus === 'waitlisted' && status === 'approved'`, use `'waitlist_approved'`. Otherwise use `status` as the email type.
    8. Send email via `sendEmail()` from `@/lib/email`. Wrap in try/catch — email failure should NOT prevent the status update from succeeding (the DB change is already committed). Log any email error.
    9. Call `revalidatePath('/admin/applications')` to refresh the table data.
    10. Return `{ success: true }`.

    **b) `addOutreachNote` action:**

    Input:
    ```typescript
    const noteSchema = z.object({
      applicationId: z.string().uuid(),
      note: z.string().min(1),
    })
    ```

    Steps:
    1. Verify caller is `approver` (same auth pattern).
    2. Update: `supabaseAdmin.from('applications').update({ outreach_notes: note }).eq('id', applicationId)`.
    3. `revalidatePath('/admin/applications')`.
    4. Return `{ success: true }`.

    **c) `getApplicationDetail` action (or utility):**

    Fetch full application detail + status history + seat availability for the slide-out panel. This can be a Server Action or a helper function called from the panel.

    - Fetch application: `supabaseAdmin.from('applications').select('*').eq('id', applicationId).single()`
    - Fetch status history: `supabaseAdmin.from('application_status_history').select('*').eq('application_id', applicationId).order('created_at', { ascending: true })`
    - Fetch seat context: `supabaseAdmin.from('zip_seats').select('total_cap, phantom_count').eq('zip_code', app.primary_zip).eq('role', app.role).single()` + count claimed seats via `supabaseAdmin.from('application_zips').select('*, applications!inner(status, role)', { count: 'exact', head: true }).eq('zip_code', app.primary_zip).in('applications.status', ['submitted', 'approved', 'waitlisted']).eq('applications.role', app.role)`
    - Resolve admin names: For each `changed_by` UUID in status history, fetch admin user email from `supabaseAdmin.auth.admin.getUserById(changed_by)`. Cache these lookups since the same admin likely made multiple changes.

    Return the full detail object for the panel to render.
