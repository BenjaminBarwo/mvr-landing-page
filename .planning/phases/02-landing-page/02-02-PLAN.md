<objective>
Build the live ZIP seat checker — the only dynamic data component on the landing page — and integrate it into the page.

Purpose: The seat checker is the core demand signal mechanism. A professional enters their ZIP code and sees exactly how many founding seats remain per role, creating urgency from real data rather than artificial scarcity. Non-Houston ZIPs are recorded as out-of-area interest signals.

Output: A `/api/seats` Route Handler querying `zip_seats` via Supabase, a `SeatCheckerSection` client component with debounced input and role-by-role display, integrated into `page.tsx` between Competitor Contrast and Role Cards sections.
</objective>

    **Route Handler (`src/app/api/seats/route.ts`):**

    Create a GET endpoint that accepts `?zip=XXXXX` query parameter.

    1. Validate ZIP: must be exactly 5 digits (`/^\d{5}$/`). Return 400 with `{ error: "Invalid ZIP code" }` if not.

    2. Create server Supabase client via `await createClient()` from `@/lib/supabase/server`. This uses the anon key — the `zip_seats_public_read` RLS policy already allows anonymous SELECT.

    3. Query `zip_seats` for the given ZIP:
       ```typescript
       const { data, error } = await supabase
         .from("zip_seats")
         .select("zip_code, role, total_cap, phantom_count, tier, neighborhood")
         .eq("zip_code", zip);
       ```

    4. If database error: return 500 with `{ error: "Database error" }`. Log error to console.

    5. If no rows returned (ZIP not in Houston):
       - Insert into `out_of_area_interest`: `await supabase.from("out_of_area_interest").insert({ zip_code: zip });`
       - Return `{ inArea: false }` with 200 status

    6. If rows returned (Houston ZIP):
       - Map rows to response format:
         ```typescript
         const seats = data.map((row) => ({
           role: row.role,
           tier: row.tier,
           neighborhood: row.neighborhood,
           totalCap: row.total_cap,
           seatsRemaining: Math.max(0, row.total_cap - row.phantom_count),
         }));
         ```
       - Return `{ inArea: true, zip, seats }` with 200 status

    7. Do NOT use service-role client. Use the same anon client.

    **SeatCheckerSection.tsx:**

    `"use client"` directive. Uses `useState`, `useEffect`, `useRef` from React. Uses `useDebouncedCallback` from `use-debounce`.

    Must use **inline styles** (React.CSSProperties) matching existing component patterns:
    - Light backgrounds (#fff cards, #f5f5f5 section bg)
    - #222 text color, font-weight 300 body text
    - IntersectionObserver for scroll-triggered fade-in animation
    - `transition: "opacity 0.6s ease, transform 0.6s ease"` pattern

    1. State: `zip` (string), `results` (SeatResult[] | null), `inArea` (boolean | null), `loading` (boolean), `error` (string | null).

    2. Debounced callback (300ms) that:
       - Only fires if value is exactly 5 digits
       - Fetches `/api/seats?zip=${value}`
       - On success: sets inArea and results
       - On error: sets error message
       - Shows loading state during fetch

    3. ZIP input styled as large centered input with light theme colors

    4. Results display: role cards showing "X of Y seats remaining"

    5. Out-of-area state: message that ZIP is not in Houston area

    6. Loading state: skeleton cards with pulse animation

    7. Section title: "Check Seat Availability"

    **page.tsx update:**
    - Import `SeatCheckerSection`
    - Add `<SeatCheckerSection />` between `<CompetitorContrast />` and `<RoleCards />` (if RoleCards exists) or before `<CoFounderCard />`
