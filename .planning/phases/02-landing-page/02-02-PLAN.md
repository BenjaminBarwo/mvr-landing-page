<objective>
Build the live ZIP seat checker — the only dynamic data component on the landing page — and integrate it into the page.

Purpose: The seat checker is the core demand signal mechanism. A professional enters their ZIP code and sees exactly how many founding seats remain per role, creating urgency from real data rather than artificial scarcity. Non-Houston ZIPs are recorded as out-of-area interest signals.

Output: A `/api/seats` Route Handler querying `zip_seats` via Supabase, a `SeatCheckerSection` client component with debounced input and role-by-role display, integrated into `page.tsx` between Competitor Contrast and Pricing sections.
</objective>

    **Route Handler (`src/app/api/seats/route.ts`):**

    Create a GET endpoint that accepts `?zip=XXXXX` query parameter.

    1. Validate ZIP: must be exactly 5 digits (`/^\d{5}$/`). Return 400 with `{ error: "Invalid ZIP code" }` if not.

    2. Create server Supabase client via `await createClient()` from `@/lib/supabase/server`. This uses the anon key — the `zip_seats_public_read` RLS policy already allows anonymous SELECT.

    3. Query `zip_seats` for the given ZIP:
       ```typescript
       const { data, error } = await supabase
         .from("zip_seats")
         .select("zip_code, role, total_cap, phantom_count, tier, neighborhood")
         .eq("zip_code", zip);
       ```

    4. If database error: return 500 with `{ error: "Database error" }`. Log error to console.

    5. If no rows returned (ZIP not in Houston):
       - Insert into `out_of_area_interest`: `await supabase.from("out_of_area_interest").insert({ zip_code: zip });`
       - Return `{ inArea: false }` with 200 status

    6. If rows returned (Houston ZIP):
       - Map rows to response format:
         ```typescript
         const seats = data.map((row) => ({
           role: row.role,
           tier: row.tier,
           neighborhood: row.neighborhood,
           totalCap: row.total_cap,
           seatsRemaining: Math.max(0, row.total_cap - row.phantom_count),
         }));
         ```
       - Return `{ inArea: true, zip, seats }` with 200 status
       - NOTE: `seats_remaining` uses `total_cap - phantom_count` for Phase 2 (no actual applications exist yet). Add a `// TODO Phase 3: subtract active application counts` comment.

    7. Do NOT use `out_of_area_interest` insert with the service-role client. Use the same anon client. The `out_of_area_interest` table should have an INSERT policy for anon. If it doesn't, the insert will silently fail — that's acceptable for a demand signal (no need to block the response on this).

    **Role display labels constant (define at top of SeatCheckerSection.tsx):**

    **SeatCheckerSection.tsx:**

    `"use client"` directive. Import `motion` from `"motion/react"`, `useDebouncedCallback` from `"use-debounce"`, `useState` from `"react"`.

    1. State: `zip` (string), `results` (SeatResult[] | null), `inArea` (boolean | null), `loading` (boolean), `error` (string | null).

    2. Define `SeatResult` interface:
       ```typescript
       interface SeatResult {
         role: string;
         tier: string;
         neighborhood: string | null;
         totalCap: number;
         seatsRemaining: number;
       }
       ```

    3. Debounced callback (300ms) that:
       - Only fires if value is exactly 5 digits (`/^\d{5}$/.test(value)`)
       - Sets loading true, clears error
       - Fetches `/api/seats?zip=${value}`
       - On success: sets inArea and results from response
       - On error: sets error to "Could not load seat availability. Try again."
       - Finally: sets loading false

    4. ZIP input:
       - `type="text"`, `inputMode="numeric"`, `maxLength={5}`, `pattern="[0-9]*"`
       - Placeholder: "Enter your ZIP code"
       - Styled: large input on dark surface background, gold border on focus, `text-center text-2xl md:text-3xl`, `bg-surface border border-gold/30 focus:border-gold rounded-xl px-6 py-4`
       - On change: update zip state, trigger debounced callback
       - Only allow numeric characters (strip non-digits on change)

    5. Results display (when `results` is not null and `inArea` is true):
       - Section header showing ZIP code and neighborhood/tier info
       - Grid/list of role cards, each showing:
         - Role label (from ROLE_LABELS mapping)
         - Seats remaining in gold: "X of Y seats remaining"
         - Visual indicator: progress-bar-style fill or seat count emphasis
       - Desktop: 2-column or 3-column grid of role cards
       - Mobile: single column compact list — each role as a row with role name left-aligned and seat count right-aligned

    6. Out-of-area state (when `inArea` is false):
       - Message: "This ZIP code is not currently in the Houston metro area. We've recorded your interest — enter your email below to be notified when we expand."
       - Do NOT actually build an email capture form (Phase 3+ concern). Just show the message.

    7. Loading state:
       - Show 6 skeleton cards (one per role) with pulsing animation
       - `animate-pulse bg-surface rounded-xl h-20` placeholders

    8. Error state:
       - Show error message in muted red/warning text
       - Allow re-entry of ZIP

    9. Wrap the entire section in `motion.section` with `whileInView` animation consistent with other sections:
       `initial={{ opacity: 0, y: 40 }}`, `whileInView={{ opacity: 1, y: 0 }}`, `viewport={{ once: true, amount: 0.2 }}`

    10. Section title: "Check Seat Availability" in serif, with subtitle "Enter your ZIP code to see remaining founding seats by role."

    11. Spacing: `py-32 px-6`, section `id="seat-checker"`
