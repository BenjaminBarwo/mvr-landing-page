**actions.ts** — "use server" module with three server actions:

1. `updateZipSeat({ id: string, field: "total_cap" | "phantom_count", value: number })` — validates approver role via requireApprover() helper (copy pattern from applications/actions.ts), validates value >= 0, updates zip_seats row via supabaseAdmin, calls revalidatePath("/admin/seats"). Returns `{ success?: boolean; error?: string }`.

2. `bulkSetPhantomFill({ role: string, phantomCount: number })` — validates approver, updates ALL zip_seats rows matching the given role to the specified phantom_count. Returns `{ success?: boolean; error?: string; updatedCount?: number }`.

3. `resetCapsByTier({ role: string })` — validates approver, resets total_cap to default tier values for all ZIPs of the given role. Default caps by role and tier (from CLAUDE.md):
   - Agent: premium=5, standard=8 (5*1.5=7.5 rounded up), suburban=10 (5*2)
   - Lender: premium=3, standard=5, suburban=6
   - Inspector: premium=2, standard=3, suburban=4
   - Title: premium=2, standard=3, suburban=4
   - Appraiser: premium=2, standard=3, suburban=4
   - Contractor: premium=3, standard=5, suburban=6
   Uses supabaseAdmin to update zip_seats with the correct cap per tier. Returns `{ success?: boolean; error?: string }`.

Also include `requireApprover()` helper (identical pattern to applications/actions.ts).

Also include `fetchSeatsForRole(role: string)` as a server action that returns all zip_seats rows for the given role, along with claimed_count (count of non-draft, non-rejected applications per ZIP+role). Query pattern:
- Fetch zip_seats WHERE role = role, ordered by zip_code
- For each ZIP, count applications matching that zip+role with status NOT IN (draft, rejected)
- Return as array of `{ id, zip_code, tier, neighborhood, total_cap, phantom_count, claimed_count, total_displayed }` where total_displayed = claimed_count + phantom_count
