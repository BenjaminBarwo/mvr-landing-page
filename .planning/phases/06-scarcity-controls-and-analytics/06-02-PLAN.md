**src/app/api/track/visit/route.ts** — POST endpoint:

- Accepts JSON body: `{ path?: string, session_id?: string, utm_source?: string, utm_medium?: string, utm_campaign?: string }`
- Creates a simple hash of the request IP using a basic approach (e.g., take request headers `x-forwarded-for` or `x-real-ip`, hash with a simple string operation — NOT crypto-grade, just for basic dedup)
- Inserts into `page_visits` via supabaseAdmin (bypasses RLS): `{ path: body.path || '/', session_id: body.session_id, utm_source: body.utm_source, utm_medium: body.utm_medium, utm_campaign: body.utm_campaign, ip_hash }`
- Returns 200 `{ received: true }` on success
- Returns 500 on error (non-critical — tracking should not break the page)
- Use `await request.json()` for body parsing (this is NOT a Stripe webhook — no signature verification needed)
- Rate limiting: not needed for MVP (admin-only analytics, low traffic validation site)

**page.tsx** — Server component:

Read `searchParams.range` to determine date filter:
- "7" = last 7 days
- "30" = last 30 days (default)
- "all" = all time (no date filter)

Calculate `since` date from range. Run two parallel data fetches via supabaseAdmin:

1. **Revenue aggregates** — query applications table:
   ```
   - total_revenue_cents: SUM(payment_amount_cents) WHERE stripe_payment_status = 'succeeded'
   - paid_count: COUNT WHERE stripe_payment_status = 'succeeded'
   - refund_count: COUNT WHERE status = 'rejected' AND stripe_payment_status = 'succeeded' (proxy for refunds — per research recommendation)
   - submitted_count: COUNT WHERE status = 'submitted'
   - approved_count: COUNT WHERE status = 'approved'
   - rejected_count: COUNT WHERE status = 'rejected'
   - waitlisted_count: COUNT WHERE status = 'waitlisted'
   ```
   Apply `created_at >= since` filter if range is not "all".

   Since Supabase JS client doesn't support FILTER(WHERE...) in aggregate queries, use separate count queries for each status with `.select('id', { count: 'exact', head: true })` and appropriate `.eq()` / `.gte()` filters. For total revenue, use `.select('payment_amount_cents')` with filters and sum client-side, OR use supabaseAdmin.rpc if a function is available. Simplest approach: fetch all payment_amount_cents values with status filters and sum in JS (applications table will be small at MVP scale — well under 1000 rows).

2. **Funnel metrics** — five step counts:
   - Visits: COUNT from page_visits WHERE visited_at >= since (if range != "all")
   - Step 1 submits: COUNT from applications WHERE step1_completed_at IS NOT NULL AND step1_completed_at >= since
   - Step 2 submits: COUNT from applications WHERE step2_completed_at IS NOT NULL AND step2_completed_at >= since
   - Payment initiated: COUNT from applications WHERE stripe_payment_intent_id IS NOT NULL AND created_at >= since
   - Payment complete: COUNT from applications WHERE stripe_payment_status = 'succeeded' AND paid_at >= since

Pass revenue data to KpiCards and funnel data to FunnelSteps.

Date range selector: render 3 buttons/tabs ("7 Days", "30 Days", "All Time") that link to `?range=7`, `?range=30`, `?range=all`. Active button highlighted.

Page title: "Analytics".

Dark theme consistent with admin: bg-black, text-white, border-gray-800.

IMPORTANT: Do NOT add navigation links to the layout in this task — that is handled in Plan 03 Task 2 to avoid file conflicts between parallel plans.
